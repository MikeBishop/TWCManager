### B3. Command routing

- Producers -> queue: `queue_background_task` routes `cmd in VEHICLE_COMMANDS = {"charge","applyChargeLimit"}` (TWCMaster.py:26, :1309) to `vehicleCommandQueue.put`; `TWCSlave._queueChargeRate` queues `setChargeRate` (TWCSlave.py:300-312); `TeslaAPIEVSE.setTargetPower` queues `fleetSetChargeRate` naming its own TeslaAPI module (TeslaAPIEVSE.py:162); stops/starts via `TWCMaster.stopCarsCharging/startCarsCharging` (:1935, :1922; `chargeStopMode` 1/2/3).
- Queue keys: `("charge", vin)`, `("applyChargeLimit", vin)`, `("setChargeRate"|"fleetSetChargeRate", vehicle.VIN)`; None = every vehicle (VehicleCommandQueue.py:64-71). A new put replaces the pending entry in either table; stop-charge goes to `_high`. `cancel(cmd, match)` and `queued(cmd, match)` drop/inspect pending (running not cancelled).
- Worker dispatch (`_DISPATCH`, :40-54): resolved module = first of VehiclePriority, HomeAssistant, TeslaBLE, TeslaAPI (`_resolveVehicleCommandModule`, TWCMaster.py:1337); `fleetSetChargeRate` bypasses it.
- `VehiclePriority.__getattr__` -> `_dispatch` (VehiclePriority.py:134): walk `master.getModuleByPriority("Vehicle", p)` from 100 down; priorities static in `TWCMaster.calculateModulePriority` (:160): TeslaBLE 20, TeslaAPI 10, everything else None (so HA is never reached). Retries = priority // 10 (BLE 3 attempts, API 2). First truthy non-"error" return wins; "error" counts as failure. `COMMAND_METHODS` (:20-28) are gated by `_skip_module_for_command` (commandPolicy `prefer_ble`/`ble_only`/`api_only`, :65-76) and `_skip_read_only_for_command` (`readOnly is True`, :78-87); `applyChargeLimit` adds caller-side `skip`/`only` for `remoteOnly`/`localOnly`.
- commandPolicy source: config `vehicle.commandPolicy` (hard override) else `settings["commandPolicy"]` (default `prefer_ble`) (VehiclePriority.py:34-60). Also consulted directly by `PresenceHandlers.hasRemoteChannel` (PresenceHandlers.py:22), `TeslaAPIEVSE._commandPolicy` (:136), and TeslaAPI (:2531, :2688).
- Not routed through VehiclePriority: all reads (`getCarApiVehicles()` callers: Policy.py:273, TWCSlave.py:321/821/1474, WebIPCControl.py:347, ChargeLimitRules.py:140/173/184, PresenceSources.py:40, TeslaAPIController.py:161, Telemetry.py:274); only `updateChargeAtHome` ("checkCharge" background task, TWCManager.py:321) goes through it. Presence probes use `PresenceSources` (telemetry, BLE `probePresence`, API `vehicleOnlineStates`) with no wake.
- Charge-limit decision rules (shared, pure): `decideChargeLimit` (ChargeLimitRules.py:35), `needsLiveRead` (:~99), `telemetryChargeLimit` (:~114), stamps `noteChargeLimitRead/Write(+For)`, `latestChargeLimit`, `ownWriteIsNewer` (:~131-218). Used by TeslaAPI.applyChargeLimit (:1090) and TeslaBLE.applyChargeLimit (:794); `sendWhenUnknown` False for API, True for BLE. HA has its own `applyChargeLimit` (HomeAssistant.py:586) and does not use these rules.
- Arrival/departure: `VehiclePresence` handlers (PresenceHandlers.py) queue `applyChargeLimit` with `vin`, `remoteOnly` or `localOnly`; limit `-1` = restore saved outside limit.

### B4. EVSE layer (#483) and relation to Gen2

- Controllers registered: `Gen2TWCs` always (TWCMaster.py:138-141, `allEVSEs` = `master.getSlaveTWCs()`, `maxPower` = `wiringMaxAmpsAllTWCs` x volts x phases); `TeslaAPIController` auto-registered when TeslaAPI loaded (TWCManager.py:738-751); `Gen3TWCs` when `controller.Gen3TWCs.enabled` (:757-768). Base class EVSEController/EVSEController.py (`allEVSEs`, `maxPower`, `startAllCharging`/`stopAllCharging`, `stop`; note `startAllCharging` has no callers per zero-stop review).
- Instances: `Gen2TWC(EVSEInstance, TWCSlave)` (EVSEInstance/Gen2TWC.py:14; `setTargetPower` :133 stores `_evseTargetAmps`); `Gen3TWC`; `TeslaAPIEVSE` (cached per VIN in `TeslaAPIController._evse_cache`, TeslaAPIController.py:~148-163; `minPower` 5 A, `maxPower` from `vehicle.availableCurrent`, `setTargetPower` 0 W is a no-op, `ble_only` suppresses it, else queues `fleetSetChargeRate`); `MergedEVSE` (EVSEInstance/MergedEVSE.py:20) merges instances with the same `currentVIN`, prefers local for `setTargetPower` (:145).
- `TWCMaster.distributeEVSEPower` (TWCMaster.py:504): returns immediately unless some controller other than Gen2TWCs is registered (so pure-Gen2 installs stay on the per-slave logic); builds `getDedupedEVSEs()` (:474); `available_watts = getMaxAmpsToDivideAmongSlaves() x voltage x phases`; filters `wantsToCharge and not isReadOnly`; ascending-`maxPower` fair share, capped by EVSE `maxPower` and by per-controller budget / remaining count; offer below `minPower` becomes 0; zero-out for EVSEs not wanting power. Single pass, single thread (main loop).
- Gen2 per-TWC amps: `TWCSlave.send_master_heartbeat` (TWCSlave.py:594; amps block ~:925-1010): if `_evseTargetAmps` is not None use it directly (`desiredAmpsOffered = target`, flex 0) else legacy path `getMaxAmpsToDivideAmongSlaves()` minus other slaves' actual amps, fair-share by `num_cars_charging_now()`; then `chargeRateControl` 1/2/3 (TWC / Tesla API / TWC >= 6 A + API), 6 A spike workaround, dampening, timing guards. `chargeRateControl` and `chargeStopMode` are `settings` keys.
- Who supplies the budget: Policy thread -> `setMaxAmpsToDivideAmongSlaves` / `checkGreenEnergy` background task (TWCManager.py:383 `check_green_energy`) -> `getMaxAmpsToDivideAmongSlaves`.
- Fleet EVSE eligibility (TeslaAPIController.allEVSEs :~118-163): `isPluggedHome(vin)`, not served by a TWC (`_twcServedVINs`), not blocked by a blind VIN-less TWC unless `bleSilent` and not TWC-attributed (`_umcCar`); departed EVSEs get queued rates cancelled (`_cancelPendingRates`).

### B5. Observations relevant to a threaded rework (facts only)

- The distributor and `TWCSlave` heartbeat amps run on the same serial thread; Fleet rate commands already hop to the worker, Gen2 amps do not.
- `settings` is mutated from the serial thread, background thread, worker, HTTP threads, and BLE under `_bleLock` with no settings-level lock (final-review.md M9).
- Locks that exist: `backgroundTasksLock`, `VehicleCommandQueue._cond`, `VehiclePresence._lock`, `TeslaBLE._bleLock`, `TeslaAPI.vehicleListLock` (RLock), `Policy._evalLock`. None for token slots or `carApiVehicles` attribute reads.
- Ordering invariant documented in review: BLE lock -> presence lock, never reverse; presence lock never held across I/O; queue `_cond` never held while calling modules (final-review.md Strengths).
- Per-vehicle state is split across `CarApiVehicle` attrs, TeslaBLE VIN-keyed dicts, `settings["chargeLimits"]`, `VehiclePresence` dicts, HA `HaVehicle`, and `Telemetry.vehicles`; none keyed by one registry object.
