# Live failure 2026-10-16 00:00: Scheduled limit 70 never reached the car (464d83c)

Read-only diagnosis. Line numbers are for 464d83c unless marked; the same code is
unchanged at 1028283 except where noted. Scratch worktrees were wt-464, wt-102 and
wt-cfd in the session scratchpad.

## TL;DR

After a restart, a car that is plugged into a Gen2 and asleep is never "present". The
TWC never reports a VIN, and `CarApiVehicle.atHome` stays at its class default `False`
because nothing recomputes it without a plug-in or power-flow edge. So `applyPolicyLimit`
gets an empty target list, no CHARGE_LIMIT desire is ever written, and the reconciler
has nothing to plan. Main/cfd0086 does not need the edge. It treats a persisted
`chargeLimits` entry as "was at home" and reads TeslaMate's location for free on each
apply. Phase 3 migrated that entry into `heldLimits`, but presence no longer reads it.
**Still present at 1028283.** A scratch repro passes (that is, it shows the bug) on both
commits.

## 1. Root cause: where the chain stops

Policy → decision-maker → desired:

- `Policy/Policy.py:321` `enforcePolicy` calls `master.setPolicyLimit(70, transition=True)`
  at 00:00:07. It also does this on every later policy tick with `transition=False`.
- `TWCMaster.py:1840-1843` `setPolicyLimit` calls `applyPolicyLimit(self, 70, decision=True)`.
- `Vehicle/Reconcile/Targets.py:83-93` `applyPolicyLimit` loops over
  `presentVehicles(master, SET_CHARGE_LIMIT)` (`Targets.py:33-41`). **The list is empty, so
  it writes no `desired.set` and touches nothing. This is where the chain stops.**

Presence, `Targets._present` (`Targets.py:18-30`):

- Not anonymous. There is no anonymous vehicle either, because a Gen2 plug session begins
  only when amps flow ≥1 A (`TWCMaster.py` `num_cars_charging_now` → `_plugSession(…, True)`,
  about line 1298).
- `vehicle.value("twcVin")` is empty. A Gen2 asks for the VIN only once amps flow
  (`TWCMaster.py`, `getVehicleVIN` queued in the same block), and a sleeping car never
  draws current. Live `lastVIN` was "" throughout.
- `api = vehicle.attachment("TeslaAPI")` exists: the Owner token listed the car, and the
  22:04:19 line "Tesla vehicle ID … is 5YJ3…: kept normal limit 100%" shows the list
  loaded. So `_present` **returns `bool(api.atHome)` = False and never reaches the
  `TeslaBLE` claim fallback** at line 30. The Owner API attachment makes the car less
  present than a BLE-only car would be.
- `atHome` is a plain class attribute, `atHome = False` (`Vehicle/TeslaAPI.py:1656`; at
  1028283 it is `:1596`). It is assigned only in three places:
  - `update_location` (`TeslaAPI.py:1927-1939`; at 1028283 `:1829-1841`)
  - `update_vehicle_data` (`:1996`)
  - `vehicleIsDefinitelyHome` (`:1553-1592`)

  The callers of those are:
  - `onDeparture` (`Targets.py:111`), which is queued only on a power-drop edge
    (`TWCSlave.py:718-726`).
  - `vehicleIsDefinitelyHome`, which is queued only when a VIN is recorded while charging
    (`TWCMaster.py:~1541`).
  - The Sources read path, which runs only for reads something asks for.

  **No startup path, periodic path or policy path locates the car.** `onArrival`
  (`Targets.py:96`, via `TWCManager.py:311`) is queued only when power starts flowing
  (`TWCSlave.py:710-716`).
- TeslaMate does feed location. `TeslaMateVehicle.py:67-68` maps `latitude`/`longitude`
  to the `lat`/`lon` RegistryFields, so `car.lat` reads <home latitude> (home). But **nothing turns
  that observation into `atHome`**: `atHome` is computed only inside `update_location` and
  `update_vehicle_data`. This is the regression from main. Main's `update_location` with a
  telemetry `syncSource` computes `atHome` from TeslaMate's position at no cost
  (cfd0086 `TeslaAPI.py:2149-2164`).
- So **yes**: after a restart with the car already plugged in and asleep, presence is lost
  for good. It stays lost until power flows (which needs the limit raised first, a
  deadlock), the car is unplugged and replugged, or `/api/checkArrival` runs.
  `checkArrival` runs `onArrival` → `applyPolicyLimit`, and that still filters on the same
  `_present`. So even a manual checkArrival does nothing until something sets `atHome`.

Reconciler, handsOff, BLE readiness and the vehicle list were never reached. With no
desire, `VehicleReconciler.plan` (`Reconciler.py:236`) and `handsOff` (`:279`) never run,
so there is nothing to log at INFO, which matches the silent log. BLE was paired and
`ble_only` makes TeslaBLE the candidate, so `order.candidates` would have passed. The
vehicle list loaded at 22:04:19.

The start and the rate were also never attempted:

- Start: `TWCMaster._chargeTargets(None, START_CHARGING)` (`TWCMaster.py:204`) uses
  `targetsFor(None)`, which is `presentVehicles`. There is no anonymous session and the
  car is absent, so there are no targets.
- Rate: `TWCSlave._setCarAmps` (`TWCSlave.py:131-145`) needs `slave.vehicleKey`.
  `Gen2TWC.vehicleKey` (`EVSEInstance/Gen2TWC.py:98-112`) returns None, because it has no
  currentVIN, no anonymous session and an empty in-memory `lastVIN`. So keys=[] and there
  is no AMPS or "lift" desire, and no BLE charge-rate command. With SOC 51 and limit 50 a
  start would have been SATISFIED by "Complete" anyway (`Rules.py:13`). The limit was the
  only lever.

The scratch repro (`scratchpad/probe-livefail/test_probe_restart.py`, run against
wt-464 and wt-102) uses a real TeslaAPI with an Owner token, a scripted BLE provider,
a BLE claim, TeslaMate lat/lon at home, `heldLimits {VIN: (100, 50)}`, then
`setPolicyLimit(70, True)`. It prints:

```
attachment is car: True atHome: False lat: <home latitude> claims: ['TeslaBLE', 'OwnerAPI', 'FleetAPI']
present: False presentVehicles: []
desire: None
BLE calls: []
```

The existing tests all set `atHome = True` by hand (test_limit_wiring, test_charging_reconciler,
test_amps_reconciler, test_vehicle_endpoint …), which is why this slipped through.

## 2. What cfd0086 does instead (code + live log)

Code:

- `Policy.py:300-311` queues `applyChargeLimit(70)` on every enforce.
- `TeslaAPI.applyChargeLimit` (`:1027-1170`) works out presence from **persisted state**:
  `getNormalChargeLimit(ID)` (`TWCMaster.py:757-767`) returns `wasAtHome=True` whenever
  `settings["chargeLimits"]` has the car. The box has `{'5YJ3…': [100, 50], '1492…': [100, 50]}`.
  - 70 > lastApplied 50 gives `needToWake` and `car_api_available(applyLimit=True)`, which
    is the Fleet wake-poll path ("TestCar: deferring wake for 3 minutes", 00:14:01).
  - Then for a `ready()` car it calls `update_location()`, which is free under TeslaMate
    sync (`:2159-2162`), and `apply_charge_limit(70)` (Fleet `set_charge_limit`; cfd0086's
    TeslaBLE has no charge-limit command).
- `wasAtHome` cars also get `update_location()` on each apply. That gives a departure
  check with no edge.
- The TWC-controlled rate raise is broadcast to every BLE VIN with no TWC VIN.

A GET of `/api/getSlaveTWCs` at 00:18 showed `lastAtHome: True, lastChargeLimit: 70,

## 4. Other state seeded only by an edge that a restart skips

1. **Presence (`atHome`)**, as above. Main kept it across restarts through `chargeLimits`
   and re-derived it from TeslaMate on each apply. Phase 3 needs a plug-in or power edge.
2. **Gen2 car identity / plug session** (`Gen2TWC.vehicleKey`, `Gen2TWC.py:98-112`):
   - The anonymous session begins only when amps flow.
   - `lastVIN` lives in memory, so a restart empties it.
   - The result is `vehicleKey None`, which means no AMPS desire, no once-per-session rate
     "lift" (`TWCSlave._requestVehicleRateRaise`), and no start/stop targets for the car
     on that TWC.
   - Main broadcast `setChargeRate`/start to every BLE VIN. On the live box that BLE rate
     command was what woke the car at 00:15:09.
   - Gen3 is not affected: `_connected` starts False, so the first vitals poll synthesizes
     the rising edge (`Gen3TWC.py:139-143, 203-213`).
3. **Departure / restore** (`onDeparture`, `Targets.py:101-113`): it is queued only on a
   power-drop edge (`TWCSlave.py:718-726`).
   - A car that left while the service was down keeps the held 50% for good: the restore
     is never desired.
   - So does a car unplugged after a restart without ever drawing power.
   - Main's `applyChargeLimit` checked `update_location()` for each `wasAtHome` car on
     every apply, which detected the departure with no edge.
4. In-memory only, and acceptable (main is the same): the Desired store's records and
   adoptions, `vehicleRateRaised` (it resets to False, which re-raises once keys exist),
   and API `statusDeferral`.

## 5. Proposed fix and regression test

Shape: presence is computed from state on every policy tick, not seeded by edges. It
costs nothing beyond what main already paid.

- **`Targets._present`, `Targets.py:24-26`.** For a TeslaAPI car:
  - **Located at home:** use the car's latest known position. That is any source's
    `lat`/`lon` observation (TeslaMate, BLE, an earlier read), passed through
    `carapi.is_location_home`. Add a no-I/O helper on `CarApiVehicle` next to
    `update_location` (`TeslaAPI.py:1927`; at 1028283 `:1829`) that recomputes `atHome`
    from `self.lat`/`self.lon`/`gpsAsOf`, the same as main's telemetry branch. Call it
    from `_present` (or let `update_location` share it).
  - **No position known** (`lat == 10000`): treat a car we hold a limit on
    (`master.heldLimits.get(vin).held is not None`) as present. This is main's
    `wasAtHome`. Otherwise fall through to the HA/BLE checks instead of returning False.
    `broadcastVehicles` already treats `lat == 10000` as reached.
  - **Located away:** absent.
- **Departure without an edge:** on each `applyPolicyLimit` pass (or once at startup),
  any car in `heldLimits.holding()` that the free location places away gets
  `_restore(…, decision=True)`. This is the same as `onDeparture`'s body, minus the paid
  `update_location(0)`.
- **Gen2 identity** (separate and secondary): either begin the anonymous plug session on a
  PLUGGED_STATES heartbeat, not only when amps flow (`TWCMaster.py` ~1290-1298, or
  `Gen2TWC.vehicleKey` returning `anonKey` while `reportedState in PLUGGED_STATES`), or
  persist `lastVIN`. Either way, `_setCarAmps` then reaches `_anonCars()` →
  `broadcastVehicles`, which includes the BLE car, as main did. This needs a design
  decision, because 00 is also "sleeping plugged" on a Gen2.

Regression test (`tests/unit/test_limit_wiring.py`, using `requests_mock`):

- **Setup:**
  - `setup(ble(Outcome(DONE)))`.
  - A Gen2 slave via `newSlave`, with heartbeat state 0x03, offering 48, `currentVIN=""`,
    `lastVIN=""`, and no plug session.
  - A real `new_api(master=m)` with `owner_token()` (plus a Fleet slot), and
    `addVehicle({"id":1,"vin":VIN,…})`. Do not set `atHome` by hand.
  - `v.claim("TeslaBLE", True, "paired")`.
  - `m.heldLimits.set(VIN, 100, 50)`, the migrated record.
  - TeslaMate observations `lat`/`lon` at `homeLat`/`homeLon`, `chargeLimit` 50 and
    `chargingState` "Complete".
- **Act:** `m.setPolicyLimit(50, transition=True)` (Non Scheduled), then
  `m.setPolicyLimit(70, transition=True)` (Scheduled), then `r.pass_()`.
- **Assert:**
  - `m.desired.get(VIN, CHARGE_LIMIT).value == 70`.
  - The BLE provider calls include `("setChargeLimit", VIN, 70)`, after its wake (BLE is
    local: a failed wake still sends).
  - `heldLimits.get(VIN) == HeldLimit(100, 70)`.
  - `requests_mock` saw no `vehicle_data`, `wake_up` or `/command/` request: presence
    cost nothing.
- **Variants:**
  - (a) No TeslaMate position (`lat` unknown) with the held limit: still present, still
    sends 70.
  - (b) The TeslaMate position is far away: absent. The held 50 is restored to 100 as a
    `restore` desire, with no paid read.
  - (c) No held limit, no position and no BLE claim: absent. This guards against waking a car of
    unknown location. With a BLE claim, the BLE fallback applies.
  - (d) The Gen2 identity part: an AMPS/lift desire reaches the BLE car with no TWC VIN.
